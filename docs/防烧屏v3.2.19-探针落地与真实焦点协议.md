# 防烧屏 v3.2.19 —— 探针为什么一直是 0，岛为什么上不去

这一版只修两件事：**让探针真的能落地**、**让图标与焦点通知按真实协议走**。快手红点与右侧列的隐藏规则仍然没写——因为到现在一份节点数据都还没拿到，按你的规矩不能凭猜落规则。

## 一、探针（NDUMP）为什么一行为 0

你那份 170 行日志里，快手（`com.smile.gifmaker`）已经在前台 8 次，`MASK connected` 也在，但 `NDUMP` 一行没有。原因只有一个：**探针被「诊断日志」开关挡住了**。

`maybeDumpNodes` 里第一道判断是 `if (!Config.enableLog) return;`，而这个开关默认是关的。也就是说：探针确实被触发过，但在写任何一行之前就返回了；你看到的所有 `SELF`、`CONF`、`MASK` 行都是不走这个开关的另一条链路写的。所以"探针跑了但日志里没有"不是写盘失败，是根本没跑。

这一版：

- 探针不再看「诊断日志」开关，只看两件事——**前台包是不是视频 App（VideoApps 名单）**、**同一个包 10 分钟内只跑一次**。最多 120 行，扫一次 3000 节点，成本比一次页面重绘还低。
- 增加 `emitProbe()` 作为唯一出口：先走 `ConfStore.appendDirectText`（本进程直写 → 失败 su 追加），两条都失败时**直接写进模块私有镜像 `files/hook-injected.log`**，下次导出/常驻补录会并回公共日志。这样"写了但被拦"也不会再丢。
- 拿不到活动窗口时照样留一行 `NDUMP pkg=… empty`——快手可能是全屏 SurfaceView，没有这一行你永远不会知道是哪种情况。

**下次验证方法**：打开快手 → 进到播放页 → 停留 3 秒 → 导出日志，搜 `NDUMP`。应该能看到 `r=corner / r=right / r=bottom` 三类行，带类名、资源 id、四边坐标、文本。

## 二、超级岛：不是配置问题，是键名全错

我把 `hyperisland-kit` 0.4.5 的源码从 Maven Central 拉下来了（`io.github.d4viddf:hyperisland_kit`，它的 GitHub 仓库是 404，但发布物在中央仓库里），逐字段对了一遍。之前两版是按旧文档反推的，**键名基本都不对**：

| 旧写法（3.2.16~3.2.18） | 真实字段（kit 源码） |
|---|---|
| `param_v1` + `param_v2` 双写 | 只有 `param_v2`，顶层另有 `title`/`content`/`isShowNotification` |
| `protocol: 1` | `protocol: 3` |
| `islandType/islandIcon/islandText` | 不存在这些键；真实是 `islandProperty/islandPriority/islandTimeout/islandOrder/dismissIsland/maxSize/needCloseAnimation/highlightColor` |
| 岛的文字塞在 `iconTextInfo`/`smallIsland`/`bigIsland` | 文字来自 `baseInfo`（`type/title/content/picFunction`） |
| 图片 key 叫 `key_island_icon` | 必须 `miui.focus.pic_` 前缀，且 `picFunction` 要指到同一个 key |
| extras 在 Builder 上用 `addExtras` | **build() 之后**直接写 `notification.extras`，Builder 阶段的会被覆盖 |
| 渠道 `IMPORTANCE_LOW` | 必须 HIGH（HyperIsland 自己的静默渠道也是 HIGH + 关声音震动） |

所以这一版把 `IslandNotify` 整份重写成 kit 的真实结构；`GuardService` 改成"先 build 再挂 extras"，渠道抬到 HIGH（声音、震动、角标全关、`setOnlyAlertOnce`，不会响也不会重复弹）。

另外：kit 的 `isSupported()` 里有三个硬条件——小米设备、`persist.sys.feature.island` 为真、以及**焦点通知白名单**（读 `content://miui.statusbar.notification.public` 的 `canShowFocus`）。你之前发的那张 HyperIsland「破解焦点白名单」页要保证是**开着**的，否则不管字段多正确，SystemUI 都当普通通知处理。这一层我们改不了，只能由 HyperIsland 那侧放行。

## 三、图标：只留一个，且和岛解耦

3.2.17 是 `smallIcon` + `setLargeIcon` 两条样式叠加 → 左右各一个；3.2.18 去掉大图后，因为你那台机器没采用焦点通知的图片 → 两边都空。

这一版：

- `setSmallIcon` 直接用 `R.mipmap.ic_launcher`（应用图标本身，HyperOS 会按 App 图标渲染在通知行左侧，跟隔壁 SafeWalk 一样就一个）。
- **永不调 `setLargeIcon`**，不会再出现第二个。
- 岛能不能上另算，图标与岛彻底解耦：岛失败也不影响通知行有图标。
