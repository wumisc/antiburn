# 防烧屏 v3.2.18（vc 117）

这一版只围绕一件事：**通知图标只留一个，而且必现**。

## 一、为什么 3.2.17 会「多一个」又「全没了」

你两张截图正好把两个 bug 都暴露了：

- **1:46 左右各一个**：我同时走了两条路 —— `setLargeIcon`（系统通知行右侧的大图）和焦点通知的 `miui.focus.pics`（HyperOS 在左侧画的 App 图标）。两套样式叠在一行上，就成了两个。
- **1:48 两边都空**：图标是用 `getApplicationIcon()` 现场画 192px 位图，构造失败被 `catch` 吞掉，退成了不可见的 `ic_tile`。所以同一个版本，一次有图一次没图。

## 二、改法

1. **图标改成资源引用**：`Icon.createWithResource(ctx, R.mipmap.ic_launcher)`，失败退 `R.drawable.ic_launcher_fg`。系统按密度自己解，不经过我们的 Canvas，不会构造失败；也不再分配位图（省内存、省 GC）。
2. **两条路二选一**：
   - 「超级岛联动」开着 → 只挂焦点通知图片（HyperOS 在左侧画 App 图标），**不设** `setLargeIcon`；
   - 联动关着 → 没有焦点样式，才补 `setLargeIcon`。
   
   两个分支互斥，任何配置下都恰好一个图标，不会左右各一个，也不会两边都空。
3. 顺手删了一处死代码（`IslandNotify.supported()` 从未被调用）。

## 三、这一轮全量检测的结果

- **测试**：946 项全绿，0 失败（T-85 六项重写为「恰好一个图标」口径：资源引用、不画位图、空图标不写 extras、二选一互斥、旧无条件大图已删）。
- **构建**：`assembleDebug` / `assembleRelease` 均通过，`lintVitalRelease` 通过（发布前强制 lint 无阻断项）。
- **混淆**：`-dontobfuscate` + 整包 keep 仍生效，反射类名不受影响。
- **清单/权限**：6 个权限与用途一一对应；`ConfigProvider` 已加调用方 uid 白名单（3.2.17）；无障碍服务、磁贴、前台服务的 `exported` 与 `permission` 声明正确。
- **线程**：17 处 `new Thread` 全是有名线程或一次性短任务，无主线程阻塞 IO。
- **日志链路**：本进程直写 → su 追加（10s 节流）→ 私有镜像，三级兜底齐全；`appendDirectText` 的 512KB 轮转仍在。
- **文案**：关于页「兼容名单」（旧称已清零）。

## 四、发现但没动的（等你一句话）

1. **通知渠道 IMPORTANCE_LOW**。焦点通知在部分 ROM 要求更高重要性 —— 如果这版岛上还是不出现，第一个要试的就是抬到 DEFAULT（会重建渠道，旧设置丢失）。
2. **GuardService 没查通知权限被拒**。要不要加「去授权」提示，取决于你想不想多一个弹窗。
3. **8 处硬编码包名**（`ConfStore`、`ForegroundWatch`、`LspScope`、`VideoApps`、`MainActivity`）。行为没问题，但换渠道包要改五处；要不要统一收进 `VideoApps` 常量，你定。
4. **MainActivity.kt 4298 行单文件**，拆分要重锁一批源码断言测试。
