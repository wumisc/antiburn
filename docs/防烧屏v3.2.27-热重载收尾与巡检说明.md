# 防烧屏 v3.2.27 · 热重载真正可用 + 这一轮巡检抓到的真 bug

## 一、这一版修的是什么（全部是本轮巡检抓出来的，不是猜的）

### 1. 热重载只换钩子、不收拾旧一代（最要命）
框架的 `onHotReloaded` 只保证「方法钩子被换掉」。我们上一代留下的东西它一概不管：
- SystemUI：`Controller` 的 2 秒周期 Runnable 还在 Looper 里排队，旧一代会一直扫状态栏；
- 视频 App：`DouyinHook` 的 3 秒周期、全局布局监听、挂在 decorView 上的悬浮球仍在；
- 无障碍侧：`SysOverlay` 已 addView 的浮层、`PixelShift` 的偏移都没撤回；
- 三条常驻线程：配置预取 `antiburn-conf-fetcher`、日志写 `antiburn-diag-writer`、`LivePause` 的 IO 执行器。

真机表现会是：热重载后日志翻倍、状态栏反复闪、视频里出现**两个悬浮球**、控件位置歪掉，
并且旧类加载器永久回收不掉（等于每次升级泄漏一整个模块）。

修法：新增 `HotReloadGuard` 退役总闸，在 `onHotReloading`（**旧代代码里**）依次做
`Controller / DouyinHook / SysOverlay / PixelShift / Config / LivePause / XposedInit` 的收尾；
各周期循环加 `retired` 早退标记，杜绝「正在跑的一轮又把循环排回来」。
`onHotReloaded` 用保存的 Application 重建上下文、重新派发业务引擎，成功后才置 `started=true`
（失败不再留下「自认为已启动、实际零钩子」的死状态）。

### 2. 配置预取线程不可停
`Config.ensureFetcher` 是 `while (true)`、没有退出条件。热重载后旧线程继续用旧类加载器读配置、
写文件，和新一代抢同一份镜像。新增 `stopForReload()`（置位 + `notifyAll` 唤醒）。

### 3. 日志写线程 / 直播 IO 线程不可停
`XposedInit.LOG_WRITER`（`newSingleThreadExecutor` 核心线程永不超时）与 `LivePause.IO`
同样每代泄漏一条。各自补 `stopForReload()`。

### 4. 遮罩几何「夹到上限继续涂黑」的隐患（上版遗留，这轮确认并锁死）
`OverlayGeometry` 对超屏高 1/4 的 statusBar、超屏宽/屏高 1/3 的 navBar 现在返回 `null` 拒绝整块涂黑；
调用方 `BurnInMaskService` 已确认对 `null` 有完整兜底（会记录「无可遮盖区域」并清除上一帧残块），
不会因为拒绝而 crash 或留残影。

## 三、边界

- 管理器若在 `onHotReloading` 之后仍判定「无法提供有效新一代」，本次退役已经发生、钩子会被框架撤掉，
  模块会静默停摆 —— 这是极端情况，处理办法仍是点「重启系统界面」。
- 热重载发生在每个被注入进程（SystemUI 与四个视频 App 各自独立），退役也是按进程各自执行的。
