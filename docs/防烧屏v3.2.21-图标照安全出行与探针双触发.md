# 防烧屏 v3.2.21 —— 图标照「安全出行」、岛照「安全出行」、探针双触发

三句话：图标改抄隔壁的写法；超级岛参数改抄隔壁的 JSON，并且**不再自己掐掉**；探针加第二个触发点、全程留痕。

## 一、图标：`setSmallIcon(applicationInfo.icon)`

你说去看「安全出行」怎么写的，我把它源码翻出来了（`SafeWalkNotificationManager.baseBuilder`）：

```kotlin
.setSmallIcon(android.R.drawable.ic_dialog_info)
```

——它自己用的是系统信息图标，那个彩色插画是**系统按焦点通知渲染时用 App 图标画在左边的**。也就是说：左边那个大图标不是我塞出来的，是「这条通知被当成焦点通知」时系统自己画的。

3.2.19 你截图里左边空、右边漂一张小图：那张小图是我们塞进 `miui.focus.pics` 的岛图，SystemUI 把它当"功能图标"画到右边，左边就空了。这版**彻底不写 pics**，图标只由 `smallIcon` 承担，而且照 SafeWalk 的口径取 `applicationInfo.icon`（清单里 `android:icon` 的最终资源 id，自适应图标也能用），取不到才退 `mipmap/ic_launcher`。

## 二、超级岛：参数始终下发（3.2.20 的白名单门控是我搞错了）

3.2.20 我加了个「先查 `canShowFocus`，不允许就不写 extras」。这是错的：

- HyperIsland 的「破解焦点白名单」是在 **SystemUI 侧**放行；
- 我们查的是**原始 Provider**，它照样回 `false`；
- 于是参数被我们自己掐掉——白名单破解了也等于没开。

「安全出行」5.6.16 的结论写得明白：**焦点参数始终下发**，不生效时系统自己会退化成普通通知，不需要我们替它判断。这版改回来：始终写 `miui.focus.param`，`canShowFocus` 只写一行诊断（`ISLAND focusAllowed=…`）。

JSON 也直接照抄它真机上岛的那份 `FocusNotifyParam.json`：

| 项 | 值 |
|---|---|
| `protocol` | **1**（不是 kit 默认的 3） |
| 内容区 | `param_island.bigIslandArea.imageTextInfoLeft` + `smallIslandArea` |
| 图片 | `picInfo: {type: 1}` —— 意思是「用 App 自己的图标」，所以不需要 pics |
| `timeout` | **不写**（kit 里它是"通知可见时长 ms"，安全出行写 1 是因为它是一次性提醒；我们是常驻，写了会让岛一闪就没） |
| `enableFloat` / `islandFirstFloat` | `false` / `true`（不上横幅，但第一次弹一下岛） |
| `islandProperty` | `1`（信息展示型） |

## 三、探针：3.2.19 为什么还是 0，这版怎么堵

3.2.19 的日志（188 行）里快手已经 HOOK 成功，`NDUMP` 仍是 0。窗口事件路径有两个坑：

1. **事件可能根本不来**：`onAccessibilityEvent` 只在 `TYPE_WINDOW_STATE_CHANGED` 且包名变化时才进分支。进快手那一刻事件被系统合并、或从快手首页点进播放页（包名没变），事件路径就永远不触发。→ 心跳 `step()` 里每帧补问一次 `maybeDumpNodes(foregroundPkg)`，同包 10 分钟一次，成本可忽略。
2. **失败是静默的**：旧版拿不到屏幕尺寸直接 `return`，异常也被吞。→ 现在会留 `NDUMP sched pkg=… w=… h=…`、`NDUMP … failed=…`、`NDUMP sched-fail …`，尺寸拿不到还会退 `DisplayMetrics`。

输出三路兜底不变：直写公共日志 → su 追加 → 私有镜像 `hook-injected.log`（导出时并回）。
