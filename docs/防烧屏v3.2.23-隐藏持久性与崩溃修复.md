# 防烧屏 v3.2.23 —— 藏住了又还原，是宽限期只有 3 轮

## 一、你这份日志里的两个事实

1. **隐藏其实一直在工作**：`HOOK app=kuaishou ... hid=true` 出现 **80 次**，`hid=false` 36 次。说明识别是对的、藏也对，只是来回切。你看到的「成功两三次又还原」就是这条 80/36 的曲线。
2. **进程还在崩**：`FATAL ... ForegroundServiceDidNotStartInTimeException` 这份日志里 **58 次**，版本仍是 `ver=3.2.21` —— 3.2.22 那个「先挂最小通知」的修复你还没装。进程一崩，同进程的无障碍服务跟着重启，掩码与探针的节奏全乱。

所以这版做两件事：把宽限期拉长（持久性），并把 3.2.22 的崩溃修复一并带上。

## 二、为什么会「很快还原」

`mergeWithGrace` 的规则是：这一轮没被 collector 收到的 View，如果窗口还活着，就先记一次 miss，**连续超过 `MISS_GRACE_ROUNDS` 轮才真正放出来**。原来这个值是 **3 轮**。

快手的搜索结果页（就是你截图那种：顶部「快手搜索」，中间视频，右侧「藏」，底部作者 / 话题 / 相关搜索）恰恰是最抖的页面：切视频、评论抽屉、相关搜索浮层一冒出来，右列连续几轮就收不到，3 轮一到 `releaseAll` 把已经藏好的全放出来 —— 于是「藏两三次，又冒出来」。

**改成 30 轮**：最快约 1 秒一轮，等于「连续 30 秒都收不到才认定真的翻页」。期间只要窗口还 attached 且可见就一直藏。真正翻页（主页 / 作品网格 / 合集列表）走的是 `looksLikeGridPage` 与 `hideEnabled` 的分页分支，那里是**立即释放**，不受这个宽限期影响 —— 不会出现退回主页还残留一块。

## 三、3.2.22 的崩溃修复（本版一并包含）

- `onStartCommand` 先 `startForeground(quickBuild)`，不读 prefs、不跨进程、不加岛参数；
- 失败退 `ic_tile` 单色矢量再挂一次；
- 完整版 `build()` 全部搬到 IO 线程（`statusText`、`focusAllowed` 都在里面）；
- `smallIconRes()` 检测 `AdaptiveIconDrawable` 就退 PNG 前景图（自适应图标做 smallIcon 会 `Invalid notification`）；
- `ensure()` 见到 `instance` 直接返回，断掉「起了没挂前台 → FDNS 崩 → 再起」的循环。
