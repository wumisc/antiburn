# 防烧屏 v3.2.20 —— 图标照「安全出行」写法、探针双触发、岛先问白名单

三件事：通知图标按隔壁 SafeWalk 的写法做、探针再加一个触发点并全程留痕、焦点通知改成"先问白名单再决定写不写"。

## 一、图标：照 `安全出行` 抄的

SafeWalk 那条「行走模式运行中」的通知，左侧图标是它自己的插画，写法就一句：

```java
.setSmallIcon(context.applicationInfo.icon)
```

不是裸的 `R.mipmap.xx`，而是清单里 `android:icon` 的最终资源 id。这一版同样改成 `appSmallIcon(ctx)`：先取 `applicationInfo.icon`，取不到才退 `R.mipmap.ic_launcher`。`setLargeIcon` 依旧一行都没有。

另外一件事得说清楚：3.2.19 那张截图里，通知行左边空着、右边漂着一张小图——那张图不是图标，是我们自己塞进 `miui.focus.pics` 的岛图，被 SystemUI 当"焦点卡片功能图标"画到右边去了，左侧的 App 图标因此让位。**这版把 `miui.focus.pics` 整个删掉**，岛只保留文字模板，不再往卡片里塞第二张图。

## 二、焦点通知：先问白名单，不允许就不写

`hyperisland-kit` 的 `isSupported()` 第一个条件是读小米的公开 Provider：

```
content://miui.statusbar.notification.public → canShowFocus(package)
```

白名单没放行时，写再多 extras 也只会得到一张没有左侧图标的焦点卡片。这版照着这个判定来：`focusAllowed()` 通过才写 `miui.focus.param`，不通过就保持普通通知（图标在左、标题正文都在，跟 SafeWalk 那条一样）。判定结果会写一行 `ISLAND focusAllowed=…` 诊断，下次日志能直接看到是哪一边拦的。

所以现在的行为是：**图标一定在左边**；岛只在系统允许时出现，不允许时不牺牲外观去硬塞。

## 三、探针：为什么 3.2.19 还是 0

3.2.19 的日志（188 行）里快手已经 HOOK 成功、`HOOK app=kuaishou … rgeo=…` 都出来了，但 `NDUMP` 仍是 0。窗口事件路径有两个坑，这版都堵上：

1. **事件可能根本不来**：`onAccessibilityEvent` 只在 `TYPE_WINDOW_STATE_CHANGED` 且包名变化时才进分支。如果进快手那一刻事件被系统合并、或用户是从快手首页点进播放页（包名没变），事件路径永远不触发。→ 心跳 `step()` 里每帧顺手问一次 `maybeDumpNodes(foregroundPkg)`，同包 10 分钟一次，几乎没有成本。
2. **失败是静默的**：旧版 `dumpNodesNow` 在屏幕尺寸拿不到时直接 `return`，`maybeDumpNodes` 的异常也被 `catch(Throwable ignored)` 吞掉——探针失效时日志一行都没有，只能靠猜。→ 现在会留下 `NDUMP sched` / `NDUMP fail … no-metrics` / `NDUMP sched-fail`，尺寸拿不到还会退到 `DisplayMetrics` 兜底。

输出三路兜底没变：直写公共日志 → 失败 su 追加 → 再失败写模块私有镜像 `hook-injected.log`（导出时并回）。
