# 防烧屏 v3.2.13（vc 112）

## 这一版只做一件事：把被注入 App 的日志真正带进导出文件

v3.2.12 的真机表现是「快手、红果明明已注入，导出的 antiburn.log 里却一条它们自己写的行都没有」——只有 SystemUI 的 SYS 心跳和模块自己的行。

排查结论：日志链路分两段，第二段断了。

1. 被注入的 App 进程写不了 `/sdcard/Android/Prevent burn-in/`，它的 `ENTER / INJECTED / HOOK app= / RDUMP / BDUMP / SCAN` 只能经 ConfigProvider 回传，落到模块私有的 `files/hook-injected.log`（下称镜像）。
2. 导出时靠 su `cat` 把这批镜像并进公开日志。su 在部分机型/ROM 上读不到应用私有目录，失败被静默吞掉，于是镜像整批丢失。

结果就是 SELF 汇总行能数出 `inject=kuaishou:8`（它读的是镜像），正文却一行明细都没有 —— 看日志的人只能得出「探针没探到」的错误结论。

## 修复方式

`ConfStore.exportLogs()` 在 su 合并之后追加一步 **`supplementHookMirror()`**：本进程直读自己的 `files/hook-injected.log`（应用读自己的私有目录不需要任何权限），把公开日志里还没有的行批量补进去。

- 整行去重，只追加，绝不回写镜像；
- 只收行首 10 位以上时间戳的行，SELF 汇总行过滤掉，避免每点一次导出就多一条历史汇总；
- 先走 su 追加，失败自动退回本进程直写。

同步版本锚点：`versionCode 112 / versionName "3.2.13"`，测试里 8 处版本断言一并更新。

## 装上之后怎么用

1. 覆盖安装本版，LSPosed 里作用域保持原样即可（快手 / 红果 / B站 / 抖音 / SystemUI 五项）。
2. 安装后第一次打开模块会自动停掉四个视频 App，重新打开它们就会重新注入。
3. 进快手刷两三条、停在播放页 20~30 秒。
4. 回模块点「日志（导出日志）」，等 Toast 出「日志已就绪」。
5. 取 `/sdcard/Android/Prevent burn-in/antiburn.log`。

这一次日志里应当出现三类此前一直缺的行：

- `RDUMP n=… w=… h=…` 及其后的 `RDUMP [类名#id …]`（右侧列按钮的真实 id 与坐标）；
- `BDUMP n=…` 及其后的角标明细（左上那个红点的类名与 resource-id）；
- `HOOK app=` 的 `sw= / R= / T= / B=`（各区域扫到了几个、被哪道门槛否掉）。

拿到这三类行之后，右侧互动列与红点的规则才能按真机样本落地；在此之前不动白名单，避免误藏点赞/评论等互动数据。
