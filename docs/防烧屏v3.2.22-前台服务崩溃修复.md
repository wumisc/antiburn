# 防烧屏 v3.2.22 —— 抓到真凶：前台服务 5 秒没挂通知，进程连环崩

你这份 1068 行日志终于把根因露出来了。探针不是没写，是**整个进程一直在崩**。

## 一、日志里的事实

- `FATAL ... RemoteServiceException$ForegroundServiceDidNotStartInTimeException` 反复出现 **6 次**，进程号一路换（9792 → 12359 → 14778 → 19079 → 26615…）。
- 崩溃调用链写得很清楚：

```
ConfigProvider.call → noteInject → GuardService.refreshIfDue → GuardService.ensure → startForegroundService
```

- 结果：`[mask/9792] MASK connected` 之后再**一条 MASK 心跳都没有**，`[a11y]` 行 0 条 —— 无障碍服务和它同进程，进程一崩，掩码和探针一起没了。
- 之前几轮的 `NDUMP=0` 也不是探针逻辑的问题，是这个崩法在持续发生。

## 二、为什么 5 秒没挂上前台通知

`onStartCommand` 里同步做完了 `build(this)`：`statusText()` 读 SharedPreferences，`IslandNotify.focusAllowed()` 还要**跨进程 call 小米的 Provider**。这两步任何一个被阻塞（Provider 正忙、插件进程抢占、prefs 首次读盘），`startForeground` 就 5 秒内到不了，系统直接判 FDNS 崩进程。

顺带还有一颗雷：3.2.20 那句 `setSmallIcon(applicationInfo.icon)` 指向的是 `mipmap-anydpi-v26/ic_launcher.xml` 的**自适应图标**，Android 明确不接受自适应图标做 smallIcon，抛的异常被 `catch(Throwable)` 吞了 —— 同样等于没挂上。

## 三、这版怎么改

1. **先挂最小通知，再慢慢拼完整版**：`onStartCommand` 立刻 `startForeground(NOTIF_ID, quickBuild(this))`。`quickBuild` 不读 prefs、不跨进程、不加岛参数，只放标题正文图标。
2. **两层兜底**：第一次挂失败 → 换 `ic_tile` 单色矢量再挂一次；再失败才写 `FGS fail=…` 诊断。
3. **完整版离开主线程**：`post()` 只在 IO 线程里 `postFull()`，`build()` 只允许在 IO 线程调用（`statusText` 与 `focusAllowed` 都在里面）。
4. **图标防自适应**：`smallIconRes()` 取到 `applicationInfo.icon` 后先判 `AdaptiveIconDrawable`，是就退 PNG 前景图（`ic_launcher_fg`），最后兜底 `ic_tile`。
5. **`ensure` 去重**：`instance != null` 就直接返回，不再反复 `startForegroundService`——崩溃重启的循环由此断掉。

探针、岛参数、掩码逻辑一个字没改。之前那些改动本身没错，只是被这个崩法一直打断。
