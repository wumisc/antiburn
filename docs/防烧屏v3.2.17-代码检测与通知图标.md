# 防烧屏 v3.2.17（vc 116）

本版两件事：**全量代码检测后的修正**，以及通知 / 岛补上应用图标、关于页「兼容性名单」改名「兼容名单」。

## 一、通知与超级岛：终于带头像了

你截的通知栏里，防烧屏那条左边是空的，隔壁 SafeWalk 有图。两个原因：

1. 常驻通知只设了 `setSmallIcon(ic_tile)` —— 那是磁贴用的白色单色线条图，放通知栏里等于没有；
2. 焦点通知的 `miui.focus.pics` 也用的同一个线条图，所以岛上也是一团白形。

改法：统一走 `IslandNotify.appIcon(ctx)` —— 用 PackageManager 取**应用自己的启动图标**（自适应合成后的那张水彩插画），画进 192px 位图：

- 通知：`setLargeIcon` 补上，通知栏左侧就是桌面上那个图标；
- 岛：`key_island_icon` / `key_focus_icon` 换成同一张图；
- 取图失败自动退回 `ic_tile`，绝不返回 null 让通知空一块。

## 二、全量代码检测：查出并修掉的三处真问题

### 1. 日志直写失败时整批丢行（严重）

`ConfStore.appendDirectText()` 本进程直写公共日志，写失败就直接 `return false`。但 Android 11+ 的 `/sdcard/Android` 是 FUSE 层拦截，跟目录 0777 无关，实际经常写不进 —— 结果无障碍探针（NDUMP）采到的行直接丢，你又会看到「日志里没有 RDUMP」。

现在改成三级：`writeDirect()`（本进程直写，保留 512KB 轮转）→ 失败 `suAppend()`（su 追加，**10 秒节流**防授权弹窗风暴，两个目录都落）→ 才认输。这样 NDUMP 与 Provider 交回的行都有兜底。

### 2. 探针等于没过滤（性能）

`maybeDumpNodes()` 里的判据是 `VideoApps.of(pkg) == null`。但 `of()` 对任何包都返回 `Kind`（未知是 `Kind.NONE`），**never null** —— 这条判断恒假，等于没生效：切到微信、桌面、相册也会扫 3000 个节点、往日志灌 200 行。

改成 `VideoApps.of(pkg) == VideoApps.Kind.NONE`，只对抖音/红果/快手/B站跑。

### 3. ConfigProvider 只靠硬编码 token（安全）

Provider 是 `exported=true`，防线只有一个写在 dex 里的常量 token，谁反编译都能拿到 —— 可以读走配置、也能往公共日志灌垃圾。

加了调用方白名单：`Binder.getCallingUid()` + `getPackagesForUid()`，只放行本模块、`com.android.systemui`、四个视频 App、root/shell；其余一律按「没带 token」处理。校验点在 token 之后、任何读写之前。

## 四、检测过的、确认没问题的项

- **版本一致性**：`build.gradle` 116 / 3.2.17，测试 8 处版本锚点同步，签名指纹 `761ef2ac…6db993` 不变。
- **线程**：17 处 `new Thread` 均有名字或为短任务；长驻线程（日志补录、conf-sync、diag-writer、live-io）都是 daemon，无悬挂。
- **静态引用**：无 `static Context` 泄漏；`DouyinHook` 的 View 列表每轮 `clear()` 重建，跨页不持有旧 View。
- **无障碍节点**：`minSdk 33`，`AccessibilityNodeInfo.recycle()` 自 API 33 起是空实现，探针不 recycle 不构成泄漏。
- **空 catch**：160 处 `catch (Throwable ignored)`，全部位于 Hook / 宿主进程代码，属于「绝不拖垮宿主」的既定约定，不是吞错。
- **混淆**：`-dontobfuscate` + 整包 keep，反射类名不会被 R8 改动；lintVitalRelease 通过。
- **包体**：APK 3,805,685 B（与 3.2.16 持平，新增代码被 R8 裁掉同类量级）。

## 五、发现但**没动**的问题（等你定）

1. **通知渠道是 IMPORTANCE_LOW**。焦点通知上岛是否需要更高重要性，各 ROM 不一样。如果这版装上岛还是不显示，第一件事就是试把渠道抬到 DEFAULT（会重建渠道，旧设置丢失）。
2. **GuardService 没检查 POST_NOTIFICATIONS**。通知权限被拒时前台服务仍跑，但通知不显示 —— 要不要加一个「去授权」提示，取决于你想不想再多一个弹窗。
3. **MainActivity.kt 4298 行单文件**。功能没问题，但改一处要滚动半天。要不要拆（拆了要重锁一批源码断言测试）。
