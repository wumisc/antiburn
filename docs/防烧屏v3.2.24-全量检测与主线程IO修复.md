## 一、查出的真问题：探针写盘在主线程，可能 ANR

`emitProbe` 的调用点全在无障碍服务主线程（`step()`、`onAccessibilityEvent`、延迟的 `dumpNodesNow`）。它内部：

```
ConfStore.appendDirectText(body)
  → writeDirect 失败（分区存储被 FUSE 拦，真机上经常失败）
  → suAppend → execSu → Process.waitFor 最长 4 秒
```

也就是说：**只要出现一次 su 授权弹窗，无障碍服务主线程就被卡住**，系统按无响应处理，随即断开绑定、把开关自动关掉——和 3.2.1 那次「无障碍崩溃」是同一条路。

修法：`emitProbe` 改成投递到专用单线程 `antiburn-probe-io`（daemon），写盘、su、镜像兜底三路全部在后台完成；线程池关闭时直接丢这一行，**绝不在调用方线程补写**。

顺带核对过：`maskDiag` 的直写只有一次小 append（无 su），`suIo` 那条本来就在后台；掩码路径没有第二处主线程阻塞。
