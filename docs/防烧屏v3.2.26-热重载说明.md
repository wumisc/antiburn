# 防烧屏 v3.2.26 · 覆盖安装后真正热重载（不再要求重启系统界面）

## 一、你问的那句：是不是只做了个标识？

是。**之前只拿到了 API 102 的「身份」，没达到热重载的「标准」。** 三处都缺：

1. `module.prop` 里只有 `minApiVersion=101 / targetApiVersion=102 / staticScope=true`，**缺 `autoHotReload=true`**。
   API 102 文档写明这是可选属性：不写，覆盖安装就不会自动触发热重载。
2. `onHotReloading()`（旧代码里执行）**默认实现直接 `return false`** —— 返回 false 就是「取消本次热重载」。
   我们之前没覆写，等于每次覆盖安装都被自己拒掉。
3. `onHotReloaded()`（新代码里执行）我们**只打了一行日志**。框架明确写了：热重载**不会重放**
   `onPackageLoaded / onPackageReady`，模块必须自己在 `onHotReloaded` 里重新装钩；否则就算热重载成功，
   进程里也没有任何钩子在工作。

所以「API 102」只代表管理器愿意按新规则加载你；真正免重启干活，要上面三条全补齐。

## 二、这次做了什么

- `module.prop` 增 `autoHotReload=true`。
- `onHotReloading` 返回 `true`，并把宿主 `Application` 通过 `setSavedInstanceState` 交给下一代
  （它是宿主类加载器对象，不属于要被丢弃的旧模块类加载器，跨代传递是安全的）。
- `onHotReloaded` 真正重装这一代钩子：
  1. 遍历 `getOldHookHandles()` 逐个 `unhook()` —— 不撤会出现两代同时生效：隐藏抖动、日志翻倍、
     旧类加载器永远回收不掉；
  2. 用保存下来的 `Application` 重建上下文（新类加载器静态字段是空的，不能再指望构造器 Hook 重抓）；
  3. 重新装 Application 抓取 + 用宿主 ClassLoader 组装 `LoadPackageParam` 重新派发给业务引擎；
  4. 通过 provider 向 App 写「热重载时刻」标记。
- `HookState` 判定从「进程启动时刻 vs APK 安装时刻」改为 **`max(进程启动, 热重载时刻)` vs 安装时刻**；
  标记一变立刻作废 30 秒缓存。热重载成功后橙卡自己消失，不再骗你点重启。
- 橙卡文案补一句：支持热重载时覆盖安装会自动重载，提示会自行消失；没消失再点重启。

## 五、边界（如实说明）

- 能不能真的免重启，还取决于管理器实现：文档允许框架在拿不到「有效的新一代模块」时报告不支持热重载。
  这种情况下会退回老路径：橙卡仍在、点「重启系统界面」即可。
- 热重载只在「管理器触发的重载」里生效；如果你在管理器里手动停用/启用模块，那本来就是重新注入。
- 重装前请确认设备上**只剩一个** `io.github.wumisc.antiburn`（旧的 `…antiburn.api102` 必须卸载），
  否则两套钩子会抢同一个进程。
- 配置目录里的 `app_ver=3.2.24-api102` 是旧分支遗留键，只影响日志显示，不影响逻辑；重装后会被新值覆盖。
