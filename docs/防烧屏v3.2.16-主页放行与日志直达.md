# 防烧屏 v3.2.16（vc 115）

## 1. 抖音主页误伤：整页放行（真机截图定位）

你发的两张主页截图里，右侧空出一整条、只剩一个「藏」按钮浮着 —— 那不是 App 画出来的，是我把它藏过头了。

根因：主页的作品列表是「等尺寸封面 + 多列」的网格，最右一列刚好落进「贴右缘窄竖条＝右侧互动列」的几何规则，于是整列封面被当成按钮列透明掉；因为用的是 INVISIBLE（保留占位），留下的空槽就是那条黑边。

修法：新增网格页结构判定 `looksLikeGridPage()`，条件收得很紧 —— 单元宽 20%~38% 屏宽、高 14%~48% 屏高、至少 6 格、尺寸彼此误差 ≤10%、至少跨 2 列、累计面积 ≥30% 屏。命中就判定「这是作品列表 / 搜索结果页」，整页放行，只保留顶部 chrome 的遮罩；播放页、直播间一律不受影响（它们根本不满足网格条件）。

## 2. 日志链路：这次不再依赖 su，也不依赖你点导出

之前四份日志里 `RDUMP`/`BDUMP`/`HOOK app=` 全是 0 行，根因是「被注入进程的行写不进公共目录，靠 su 合并时被拦」。

本版换掉整条链路：

- 新增 `ConfStore.appendDirectText()` / `appendHookLine()`：**本进程直接追加进 `/sdcard/Android/Prevent burn-in/antiburn.log`**，不 fork、不等导出、不借 su。写满仍按 512KB 轮转成 `.1`。
- `ConfigProvider` 顺序改成「先写公共日志，写不进才退回私有镜像」——镜像从主通道降级为兜底。
- 覆盖安装的真清空：`clearLogs()` 先本进程直删（主日志 + `.1` + 两个目录里的 `antiburn*.log`），su 只当兜底。

## 3. 快手红点 / 右侧赞藏评转：换一条采集路（免 root、免注入）

LSPosed 侧的 `RDUMP` 一直没落地，那就不等它了。本版新增**无障碍探针 NDUMP**：

- 前台切到抖音/红果/快手/B站时，等 1.5 秒布局稳定，用无障碍读屏把「左上角 / 顶栏 / 右侧 / 底栏」四个固定区的节点导出来，直接写进公共日志；
- 每行形如 `NDUMP r=corner c=TextView id=smile.gifmaker:id/xxx b=120,540,180,600 t=12`，类名、资源 id、四边坐标、文本都有；
- 门控只有两条：诊断日志开关打开、同包 10 分钟一次；行数上限 200 行，不会把日志撑爆。

有了这几行，快手那个左上红点（类名 + id + 尺寸）和右侧四个按钮的精确锚点就能直接写规则，不用再猜阈值。

## 4. 常驻通知：标准通知 + 小米焦点通知（上超级岛）

按你说的做法：**通知本体保持标准常驻**（标题、最近保护状态、点开进模块、前台服务全部不变），只额外挂一组公开的焦点通知 extras：

- `miui.focus.param`：`param_v1`（老协议）+ `param_v2`（新协议）双写，v2 里含小岛、大岛、文字卡、`updatable`；
- `miui.focus.pics`：图片 Bundle，`key_island_icon` / `key_focus_icon` 两个 key；
- 岛文案：小岛「防烧屏」，大岛左「防烧屏 · 运行中」，右为当前状态；
- `islandTimeout=0`、`dismissIsland=false`：运行态常驻，不自动收起。

不读 HyperIsland 的任何私有配置，也不做白名单破解 —— 按你说的，超级岛增强那边默认已放开。**失败就降级**：拼不出来或 ROM 不认这套 extras，通知照旧是普通常驻通知，不会丢。门控复用「超级岛联动」开关（默认开），关掉即完全不写 extras。

## 5. 抖音直播间：还差一张图

本版没有改直播间的隐藏规则 —— 现有链路是「三区（顶/底/右）+ 固定条补扫」，缺的是**你那一版直播间的实际结构**。NDUMP 已经把直播间也算进采集范围，所以：

开着诊断日志 → 进一次抖音直播间 → 停 20 秒 → 直接把 `antiburn.log` 发我，里面会有 `NDUMP r=top/right/bottom` 那一批行。告诉我「哪个区域该藏没藏 / 哪个藏过头」，我按真机节点一次改到位，不再猜。
