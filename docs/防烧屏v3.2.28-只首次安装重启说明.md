# 防烧屏 v3.2.28 · 只有第一次安装需要重启系统界面

## 一、结论：覆盖安装不再要求重启

这版把「更新后必须重启 SystemUI」彻底拆掉，改成三条并行的路：

1. **框架热重载（优先）**：`module.prop` 声明 `autoHotReload=true`，`onHotReloading` 返回 true，
   `onHotReloaded` 撤旧代、重建上下文、重装钩子。管理器支持就秒换代码，零重启。
2. **模块自换代码（兜底，新增）**：管理器不支持热重载时，模块自己来 —— `SelfReload` 每 20 秒比对
   一次本模块 APK 的 `lastUpdateTime`，发现更新就把新 APK 用 `DexClassLoader` 就地载入：
   预检新代码 → 撤掉旧代全部 HookHandle → 退役旧代周期/浮层/线程 → 用新代入口重新派发。
   父加载器取 `XposedModule.class.getClassLoader()`（框架加载器），所以不会在 loader 链上套娃、
   旧代能真正被回收。
3. **只有第一次安装才提示重启**：`seen` 标记（模块曾在系统界面里跑过）为空才算首次安装；
   一旦跑过，橙卡不再出现。文案也已改成「首次安装需要重启一次系统界面」。

## 二、自换代码的安全设计（为什么不会把模块弄成植物人）

- **先预检，后退役**：`Class.forName("…SelfEntry", true, child)` 成功才动旧代；
  新 APK 载不进来就原地不动，继续用旧代码。
- **撤干净**：兼容壳 `XposedBridge` 现在记录每一个 `HookHandle`（包括 Application 抓取钩子），
  `unhookAll()` 整体撤销；`HotReloadGuard` 再收拾周期任务、浮层、悬浮球、配置预取、日志线程。
- **失败可重试**：新一代入口返回 `boolean`，失败不更新基线时间，20 秒后再试，不会「一次失败就永久停摆」。
- **日志写入器退役后不抛**：执行器被 `shutdownNow` 后，`write()` 捕获拒绝并直接降级 logcat，
  不会因为写不出去把调用方（乃至 SystemUI 主线程）带走。

## 三、你可以怎么核实（日志关键词）

- 首次注入：`SELFLOAD arm apk_t=… path=…`
- 覆盖安装后（20 秒内）：`SELFLOAD reload apk_t=… unhooked=N` → `SELFLOAD done apk_t=…`
- 新代接管：`SELFLOAD installed pkg=com.android.systemui proc=com.android.systemui`
- 若管理器也给了热重载：`hot reloading, savedApp=true` / `hot reloaded … unhooked=N`

## 五、边界（如实说明）

- **首次安装**仍需要重启一次 SystemUI：模块代码还没进过那个进程，任何机制都无法凭空注入。
- 自换代码依赖「新 APK 对本进程可读」。SystemUI 是 system uid，读 `/data/app/…/base.apk` 没问题；
  如果某个 ROM 的 SELinux 拦了这一步，日志会留 `SELFLOAD fail`，框架热重载仍可兜底。
- 换代码在 SystemUI 主线程执行（一次更新一次，只加载入口相关类，通常 <100ms）；
  若你的 ROM 在更新瞬间特别卡，属于可观测的一次性抖动，不是常驻开销（巡检 20 秒一次只读一个 PackageInfo）。
