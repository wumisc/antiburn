# 防烧屏 v3.2.30 · 四大视频联动 + 热重载旧代码排查 + 通用设置沙盒

## 一、这轮真查出来的 5 个问题（都已改）

### 1. 抖音 / 红果还在用「这一轮收到几个控件」决定是否隐藏 → 反复抽搐
`DouyinHook.anyEnabled` 在抖音 / 红果分支仍写成
`enableDouyinLike && !rightList.isEmpty()` 这种形式。v3.0.36 的注释已经写明
「不再把这一轮识别到几个写进 anyEnabled」，但只改了快手 / B站，抖音 / 红果漏了。
滚动、弹层、Compose 重绘必然有某一轮收集器落空，于是：

`anyEnabled=false → tick 走 showAll() → 下一秒又收到 → 再藏`

真机表现就是「藏了又露、反复抽搐」。现在四个 App 统一：
只要用户开了任一区域开关，就维持隐藏窗口；某个区域这一轮没收到目标，该区域循环
本来就是空操作，不需要靠 `anyEnabled=false` 去恢复。

### 2. `hideEnabled()` 绕过总开关 / 灭屏闸
`hideEnabled()` 会被 `onResume` 与 `onGlobalLayout` 在 `hidden=true` 时直接调用。
旧版总开关只在 `tick()` 里判，用户关掉「防烧屏保护」后再切一次页面，
事件路径仍会再藏一下固定控件，看起来就是「总开关不生效」。
现在 `hideEnabled()` 第一行统一判 `!enableStatus || !isScreenOn()`，命中就 `showAll()` 并清 `hidden`。

### 3. 自换代码成功后，旧一代 tick 还会跑完这一轮
`Controller.tick()` 只在方法开头判 `retired`。它先调 `SelfReload.check()`，
换代码成功后 `HotReloadGuard.shutdown()` 已把本代置为 retired，但旧版不复查，
继续用旧 View 引用执行 `checkViewsAlive / Config.reload / 隐藏恢复`，
和刚装好的新一代抢同一批控件 —— 换代码瞬间状态栏会抽一下。
现在 `SelfReload.check()` 之后立刻 `if (retired) return;`。

### 4. 视频钩子退役只清了列表，没清宿主 View 引用
`DouyinHook.shutdownForReload()` 旧版清了 14 个区域列表和悬浮球，但
`topBar / rightTop / leftTop / currentDecor / lastRoot` 仍攥着宿主 Activity 的 DecorView，
`missRounds`、隐藏相位、直播判定、DPH 诊断状态也原样留着。新类加载器本来干净，
但 SelfReload 失败回滚或框架复用同一加载器时，这些就是实打实的旧代码联动残留，
旧类加载器也回收不掉。现在退役时逐个置空 / 归零；`tick()` 也补了 `retired` 早退，
已出队的旧 `cycleRunnable` 即使跑起来也立即退出。

### 5. SelfReload 安装失败后「20 秒重试」永远不会发生
旧版 `SelfReload.reload()` 先 `unhookAll + HotReloadGuard.shutdown()`，再反射调
新代码的 `SelfEntry.install`。如果 install 抛异常 / 返回 false：
- 旧代已经被退役，`Controller.retired=true`，周期不再跑；
- 20 秒轮询本身就在 `Controller.tick()` 里，所以「下一轮重试」根本没有下一轮；
- 模块会一直躺到 SystemUI 重启。
现在 install 失败会立刻用旧代自己的 `SelfEntry.install(...)` 重新装回旧代码，
把 `genApkTime/genApkPath` 退回旧值，下一轮 20s check 仍会重试新版。
这是「失败不能把用户扔在半路」的兜底。

## 二、四大视频逐项核过的代码

| App | 路由（包名变体） | 区域门控 | 本轮结论 |
| --- | --- | --- | --- |
| 抖音 | `com.ss.android.ugc.aweme` / `.mobile` / `.lite` | 5 区 + 直播间 | `anyEnabled` 改为只看开关；总开关闸补齐 |
| 红果 | `com.phoenix.read` / `.oversea.gp` | 顶部/右/右上/左上/左滑，底部刻意常驻 | 同上；`enableDramaBottom` 仍不参与 anyEnabled |
| 快手 | `com.smile.gifmaker` / `com.kuaishou.nebula` | 总开关 + 右/顶/底/角落 | 原本就是开关制，未改语义；退役清理共用 |
| B站 | `tv.danmaku.bili` / `bilibilihd` / `com.bilibili.app.*` / `com.bilibili.intl` | 仅右侧点赞区，顶/底/角恒 false | 原本就是开关制；退役清理共用 |

通用设置核过：
- `Config.shouldIntervene`：总开关、white / black / off、自身包名豁免、overlay 引擎让位；
- `ConfStore.normMode / normEngine` 的旧别名兼容；
- 黑白名单迁移：只有 `blacklist` 的旧配置仍按白名单解释；
- 默认配置里四个 App 的全部键都存在且默认 0；
- `ListRules` 的空黑名单兜底语义。

## 三、沙盒实际跑了什么

JVM 沙盒共 **70 条 / 0 失败**：

| 测试类 | 条数 | 覆盖 |
| --- | --- | --- |
| `SandboxSafetyTest` | 21 | 隐身别名、自愈闹钟、通知、首次安装提示、API102 热重载交接 |
| `PureLogicTest` | 18 | 几何/名单/门控纯逻辑、module.prop 契约、SelfReload 判定 |
| `VideoSettingsSandboxTest` | 18 | 四视频路由、区域开关语义、名单/引擎、默认配置键 |
| `HotReloadLinkageTest` | 13 | 退役队列、View 引用清空、幂等、四视频共用退役闸 |

其中本轮新增的关键断言：
- 抖音 / 红果 / 快手 / B站 的主包与渠道包逐一归类，非目标包不得误判；
- `white/black/off` 三种名单模式与空黑名单兜底；
- `overlay` 引擎下 Hook 对四个 App 全部让位；
- `DouyinHook.shutdownForReload()` 后 14 个列表为空、5 个宿主 View 引用为 null、
  `missRounds` 清空、相位/直播/DPH 状态归零；
- 退役后 `startCycle` 排不进 Handler，已排的周期被撤掉，旧 `cycleRunnable` 不再排下一轮；
- `Controller.shutdownForReload()` 同样撤队列、清 View 引用、可重复调用；
- `HotReloadGuard.shutdown()` 连调两次不抛异常，Controller / 视频钩子 / 配置预取全部停。
