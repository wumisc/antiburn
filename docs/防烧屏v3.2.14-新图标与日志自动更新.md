- **背景层**：整图铺满 + 高斯模糊 + 压暗 8%，蒙版边缘不生硬；

## 二、日志不用再点按钮（上一版 3.2.13 的补录 + 本版自动更新）

3.2.13 修掉了「被注入 App 的行进不了导出日志」：导出时用本进程直读私有镜像补录。

本版再往前一步 —— 用户反馈「非得点一下按钮、等 toast 才知道日志好没好」：

- `ConfStore.autoSyncLog()`：只把镜像里还没进公开日志的行补进去，**不写 SELF、不重排、不弹提示**；
- **常驻服务每 180 秒**静默跑一次（`GuardService` 里独立排期，通知刷新仍是 3 小时 / 30 分钟，没动）；
- 打开模块时也会自动补一次；
- 成本控制：读自己的私有文件，没有新行直接 return（常态零开销）；有新行时**本进程直写一次**，不 fork su；补录改「先直写、失败才 su」；
- 受「诊断日志」开关门控，开关关着就完全不干活；读写都在单独 daemon 线程，不占主线程。

## 四、取日志的正确姿势（这轮反复踩的坑）

1. `antiburn.log` 写满会轮转成 `antiburn.log.1`，新文件从 0 行重开。**只拷主文件会只剩一两行** —— 要么连 `.1` 一起给，要么点一次「日志」让模块把两者合并（合并后是完整的一份）。
2. 装完新版要先**覆盖安装 + 重开一次视频 App**，日志里的 `ver=` 才会变成 3.2.14。看到 `ver=3.2.12` 说明跑的还是旧包。
3. 快手的探针行前缀是 `RDUMP`（右侧列按钮）与 `BDUMP`（角标 / 红点）；一条都没有，说明那批行还没进日志，不是探针没跑。
