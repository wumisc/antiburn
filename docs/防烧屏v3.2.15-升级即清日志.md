# 防烧屏 v3.2.15（vc 114）

## 这一版：覆盖安装即清空旧日志并重建（不用先打开模块）

上一轮的残留问题：设备上跑的还是 `ver=3.2.12` 的旧包，而 `antiburn.log` 又恰好是写满轮转后的残卷（只剩一行），看起来像"日志坏了"。

原方案只在**打开模块**时才清旧日志。装完直接去开快手的人根本触发不到，于是旧日志一直留着、`ver=` 一直是旧版本号，反复误判成"新版没生效"。

改动：

- 判定与清空收敛到 `ConfStore.clearLogsIfUpgraded(ctx)`，由 **`AbApplication.onCreate()`** 调用 —— 任何进程启动（包括被 Hook 拉起 Provider）都会先判一次，装完不打开模块也能触发。
- 判定口径不变：`last_vc == 0`（首次安装）不清，`last_vc == now`（同版本重复启动）不清，**只有版本号变了才清**；先记账再动手，被二次拉起不会重复清。
- 清空范围：`antiburn.log` + 轮转的 `antiburn.log.1` + 兜底目录全部 `*.log` + 私有镜像 `hook-injected.log`，一个不留。
- 清完立刻写一行起始标记：

  ```
  <时间戳> [app/self] LOG ver=3.2.15 vc=114 旧日志已清空（含 .1 与私有镜像），新日志从这里开始
  ```

  打开文件第一行就能看出"这是新日志、这是哪一版"，不必再靠行数或 `ver=` 猜。
- 若清空发生在 Application（用户还没看到界面），会留一个一次性标记，下次进模块时提示"配置已保留，旧日志已清空"。
- 行为下沉到后台线程，不等 su 授权，不阻塞启动。

## 装上之后

1. 覆盖安装 → 模块自动清空旧日志（含 `.1` 与镜像）并写入起始标记；同时自动强停四个视频 App，逼 LSPosed 重新注入新 dex。
2. 重新打开快手刷两三条、停在播放页 20~30 秒。
3. 直接取 `/sdcard/Android/Prevent burn-in/antiburn.log` —— 不用点按钮，常驻服务每 180 秒会把新行补进去；文件第一行会写明 `ver=3.2.15`。
4. 这时应能看到 `RDUMP`（右侧列按钮的类名/id/坐标）、`BDUMP`（角标/红点明细）、`HOOK app=` 的 `sw= / R= / T= / B=`。
